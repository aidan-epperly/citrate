# Development

## Layout

- `src/`: the library. The array modules are generated (see below); the others (`krylov`,
  `ode` and its parts, `cheb`, `curve`, `complex64`, `complex32`, `vec`, `types`) are
  written by hand.
- `templates/`: the source of the array modules.
- `tools/`: the generators and the Roblox test runners.
- `tests/`: the test suite (`tests/run.luau`).
- `bench/`: benchmarks.
- `demos/`: Roblox demos (`demos/cloth`: implicit cloth; `demos/drum`: the isospectral drums; `demos/flow`: a vortex street; `demos/track`: constant speed along a curve; `demos/tails`: dynamic bones at any update rate; `demos/bones`: the dynamic bones component; `demos/path`: the path component on a roller coaster; `demos/reach`: an arm reaching by least squares against CCD; `demos/flock`: spatial queries and A* routes; `demos/terrain`: marbles on bilinear and cubic heightfields).
- `roblox/`: components that use Roblox's API (`roblox/bones.luau`: dynamic bones; `roblox/path.luau`: paths through Attachments or Parts), kept out of `src/` so that the library itself runs anywhere.
- `docs/`: this documentation; `docs/reference/` is generated.

## Generated modules

`src/f32.luau`, `f64.luau`, `c32.luau` and `c64.luau` and their parts (`array_f64.luau`,
`matrix_f64.luau`, ...) are generated by `python tools/generate.py`; edit the templates. One
set of modules per element type is needed because Luau only optimizes `buffer.readf64` and
friends into fast calls when they are written out literally.

- `templates/real/<part>.luau.in` and `templates/complex/<part>.luau.in`: one template per
  part, for the real (f32, f64) and complex (c32, c64) modules.
- `templates/<family>/module.luau.in`: the combined module (`f64.luau`, ...).
- `templates/<family>/prelude.luau.in`: types and small helpers included in every part.
  They are copied rather than imported so that calls to them are inlined; the generator
  drops the ones a part does not use.
- `templates/shared/`: code shared by the real and complex families.
- `templates/kernels/`: generated by `tools/gen_kernels.py` (the register-blocked matrix
  product kernels) and `tools/gen_sparse_kernels.py` (the unrolled and block sparse kernels).

The parts are, in dependency order (each may require earlier ones): `array`, `matrix`,
`gemm`, `factor`, `fft`, `structured`, `sparse`, `eigen`, `matfun`.

Template syntax:

| | |
| --- | --- |
| `@W@`, `@E@`, `@EPS@`, `@READ@`, `@WRITE@`, `@NAME@`, `@TAG@`, ... | substituted per type |
| `--@f64 <line>` (also `f32`, `c32`, `c64`) | the line is kept only for that type |
| `--@include <path>` | replaced by `templates/<path>` |
| `--@unroll` | the next loop (over `k`) is unrolled by 4 |
| `--@optional` | the next definition is dropped where unused |
| `--@inline` | the next local function is pasted in at each call (see below) |

Element access in the templates goes through small helpers in the preludes, marked
`--@inline`, so that code reads as `load(a, at(i, k))` rather than
`buffer.readf64(a, 8 * (k * n + i))`:

- `elem(i)`: the byte offset of element i (0-based) of an array; `at(i, j)`, defined in a
  routine, the offset of entry (i, j) of its matrix. `imag(o)` is the offset of the
  imaginary part of the number at offset o, and `relem(i)` that of element i of a real
  array (the singular values in a complex module, or the i-th real number in shared code).
  Real parts also have `celem(i)`, `cload` and `cstore` for complex arrays (rfft's output).
- `load(x, o)`, `store(x, o, v)`: the real number at byte offset o.
- `add_at`, `sub_at`, `mul_at`, `div_at`, `swap_at` (real): `x[o] += v` and so on, with
  the offset computed once.
- `cload(x, o)` returns (re, im); `cstore`, `cadd_at`, `csub_at`, `cmul_at`, `cdiv_at`
  (by a real number) and `cswap_at` (complex).

The generator replaces each call by the function's body, with the arguments substituted.
Luau would inline these small functions itself, but on Roblox clients, which interpret
Luau rather than compile it, the copies in and out of an inlined call still cost 25-65% in
an LU update loop. The expanded text compiles to the same bytecode as the code written out
by hand. A function whose body is `return <expressions>` can be used in any expression;
any other is a statement, put in a `do` block if it declares locals (renamed with a
trailing `_`). Locals of the same name shadow it as in Luau. All templates use these
helpers except the generated kernels in `templates/kernels/`.

`generate.py` also writes the API reference (`docs/reference/`) from the doc comments of
the public functions, and `--check` reports anything out of date.

## Roadmap

Planned, in order:

1. Computational geometry: convex hulls, Delaunay triangulation (and meshes for `pde` on any
   polygon), polygon triangulation, point-in-polygon, closest points.
2. Frame-rate-independent smoothing: critically damped springs and second-order follow
   dynamics.
3. Constrained optimization: bounds on variables, small linear and quadratic programs.
4. State estimation: Kalman filtering.
5. Sparse least squares (LSQR or LSMR).

Goals for later:

- Fast evaluation of radial basis function interpolants (each value now costs a kernel
  evaluation per point). A first step measured: writing each kernel into the summation
  loop instead of calling it through a closure took a 4000-point Gaussian value from 69 to
  36 us natively (165 against 181 interpreted).
- Exact Jacobians and gradients by automatic differentiation, in place of finite
  differences.

## Wiki

The [wiki](https://github.com/aidan-epperly/citrate/wiki) is a copy of `docs/` for
reading on GitHub; `docs/` stays the source. After changing the docs, publish them:

```
git clone https://github.com/aidan-epperly/citrate.wiki.git ../citrate.wiki
python tools/publish_wiki.py ../citrate.wiki
cd ../citrate.wiki && git add -A && git commit -m "Update from docs" && git push
```

Each page is named by its title (reference pages with " reference" appended), links
between pages become wiki links and links to other files point to them on GitHub.

## Testing

Run the tests and the type checker with the
[Luau](https://github.com/luau-lang/luau/releases) command-line tools:

```sh
python tools/generate.py --check
luau-analyze src/*.luau tests/*.luau bench/*.luau
luau tests/run.luau
```

The same suite runs inside Roblox through Open Cloud: `tools/roblox_test.py` builds a test
place with [Rojo](https://rojo.space) (`tests.project.json`), saves it as a version of a
place you own, runs the tests there with the Luau Execution API and prints the results. It
reads `ROBLOX_API_KEY` (a key with universe-places write and luau-execution-sessions read
and write on that experience), `ROBLOX_UNIVERSE_ID` and `ROBLOX_PLACE_ID` from the
environment; saving replaces the place's contents, so use a place set aside for testing.
`--script file.luau` runs another script instead. With that place open in Roblox Studio and
Studio's MCP server enabled (Assistant settings), `python tools/studio_test.py Client` runs
the suite in a playtest client (or `Server`, or `Edit`). The few checks of behavior at
subnormal magnitudes are skipped where Roblox flushes subnormals to zero.

## Third-party code

Parts of citrate are translations of other projects' code or copy their coefficients. Each
place says so in a comment, and the projects' license notices are in `licenses/`:

- [LAPACK](https://github.com/Reference-LAPACK/lapack) (modified BSD;
  [`licenses/LAPACK-LICENSE.txt`](../licenses/LAPACK-LICENSE.txt)): the routines marked
  "(LAPACK's ...)" in the eigen, factor and structured parts and in `src/krylov.luau` are
  translations of LAPACK's reference implementations, among them the Hessenberg and
  tridiagonal reductions (sytd2/hetd2, org2r/ung2r), Francis QR
  (lahqr, lanv2), balancing (gebal), eigenvectors (trevc), the bidiagonal SVD (gebd2,
  bdsqr, lartg, las2, lasv2), the inverse (getri), the symmetric indefinite factorization
  (sytf2/hetf2, sytrs/hetrs), the tridiagonal and banded factorizations (gttrf, pttrf,
  gbtf2, pbtf2), the condition estimate (gecon), mixed-precision refinement (dsgesv) and the
  Schur reordering step (trexc).
- [SciPy](https://github.com/scipy/scipy) (BSD-3-Clause;
  [`licenses/SciPy-LICENSE.txt`](../licenses/SciPy-LICENSE.txt)): the Radau IIA and BDF
  solvers are translations of `radau.py` and `bdf.py`, and MINRES of `minres.py`; the
  DOP853 coefficients (`dop853_coefficients.py`) and the dense-output coefficients of
  Dormand-Prince 5(4) and Bogacki-Shampine 3(2) (`rk.py`) are copied, in `src/ode.luau` and
  `src/odestiff.luau`.
- [OrdinaryDiffEq.jl](https://github.com/SciML/OrdinaryDiffEq.jl) (MIT;
  [`licenses/OrdinaryDiffEq.jl-LICENSE.md`](../licenses/OrdinaryDiffEq.jl-LICENSE.md)): the
  Rodas5P tableau and dense-output coefficients (Steinebach 2023; `rosenbrock_tableaus.jl`),
  in `src/odestiff.luau`, and the Runge-Kutta-Nystrom pairs DPRKN6 (with its dense output),
  DPRKN8 and DPRKN12 of Dormand, El-Mikkawy and Prince (`rkn_tableaus.jl`, evaluated in high
  precision from their exact forms), in `src/odenystrom.luau`.
- [Chebfun](https://github.com/chebfun/chebfun) (BSD-3-Clause;
  [`licenses/Chebfun-LICENSE.txt`](../licenses/Chebfun-LICENSE.txt)): `standard_chop` is a
  translation of `standardChop.m`, and `roots` follows Chebfun's rootfinding (colleague
  matrices with recursive splitting at Chebfun's splitting point), in `src/cheb.luau`.
- LINPACK (public domain): the Cholesky update and downdate follow `chud` and `chdd`.

The other algorithms were implemented from their published descriptions, which the
comments cite.
